## 1. 背景与现状分析

### 1.1 系统简介

IPD-PMO 是面向项目管理场景的内部登记工具，核心包含三大模块：

| 模块 | 功能 | 核心数据 |
|------|------|---------|
| **项目阶段状态** | 跟踪项目阶段交付目标与实际评估 | 项目集、子项目集、子项目、阶段交付目标、实际交付评估、是否符合计划、执行过程分析、问题分析、改进计划 |
| **部门项目人力登记** | 管理部门人员在各项目中的投入占比 | 项目集、子项目集、子项目、一级/二级部门、小计、人力占比 |
| **项目风险登记** | 识别、记录并跟踪项目风险事项 | 风险类别、风险来源、项目、问题&影响、解决方案、级别、跟进人、解决时间、状态 |

### 1.2 当前 UI 现状

通过对现有 [`frontend/index.html`](../frontend/index.html) 及系统截图的审查，当前界面存在以下典型问题：

- **表格行高过大**（约 50–60px），一屏仅能展示 3–4 行数据
- **筛选区控件尺寸偏大**，按钮高度约 36–40px，字体 15–16px
- **标题区与内容区之间存在大量空白**
- **三个模块的页边距不统一**，视觉上缺乏一致性
- **表格与页面边框距离不一致**

### 1.3 参考设计分析

参照成熟项目管理系统的界面设计，并结合本仓库交互原型 `ipd-pmo-redesign.html`，提炼以下可借鉴特征：

| 维度 | 目标特征 |
|------|---------|
| 信息密度 | 表格行高约 36px，一屏可展示 15–20 行 |
| 控件尺寸 | 按钮/下拉框高度 30px，按钮字体 12px，页面基础字号 14px |
| 间距统一 | 内容区 padding 20–24px，模块间距一致 |
| 配色 | 白底 + 浅灰边框（`#e8e8e8` / `#f0f0f0`）+ 浅灰背景（`#fafafa`） |
| 交互 | 行 hover 高亮、斑马纹、筛选 change 即时过滤、底部记录数统计 |

### 1.4 已实现内容评估（对照 `frontend/index.html`）

本节基于当前仓库主应用代码的**逐项对照**，明确「已有能力 / 与原型差异 / 优化时是否保留」。此前 v1.1 未单独成节，易造成「按原型整页替换」的误解。

#### 1.4.1 品牌与顶栏（须保留，仅做紧凑化）

| 项 | 现状实现 | 原型 `ipd-pmo-redesign.html` | 优化建议 |
|----|---------|------------------------------|---------|
| 产品名 | **ProjectGuard**（`<title>`、登录页） | 文案「IPD-PMO」+ 菱形符号 | **保留 ProjectGuard**；IPD-PMO 可作为副标题或文档用语 |
| LOGO | `.app-brand` + `projectguard-logo.png`（图片自适应高度） | 无图片，纯文字 | **保留图片 LOGO**，不改为文字 Logo |
| 顶栏结构 | `.tabs-sticky`：LOGO + 居中 Tab + 右侧用户区 | `.topbar` 48px 单行 | **保留三栏结构**；将 `--nav-vh-eighth`（视口 1/8，约 120px+）**压缩为固定 48–56px** 或 `min(56px, 12vh)` |
| 主色 | CSS 变量 `--accent: #1677ff`（Ant Design 5） | `#1890ff` | **沿用 `#1677ff`**，与 `login.html` 一致 |
| 用户区 | `#pm-nav-user-hint`（用户名 · 角色）+ `#pm-btn-logout-nav` | 圆形头像「S Sky」 | **保留现有提示 + 退出**；头像为可选增强 |
| 布局宽度 | `.app-wrap` `max-width: 1240px` 居中 | 全宽 `padding: 20px 24px` | 可讨论是否放宽至 100%；默认**保留 max-width**，避免超宽屏表格难读 |

#### 1.4.2 导航与模块（比原型多一项）

| Tab | 面板 ID | 现状 | 原型 | 优化建议 |
|-----|---------|------|------|---------|
| 项目阶段状态 | `panel-phase` | ✅ 年月选择 + 动态表格 + 编辑/保存 | 项目集下拉筛选 | **保留年月维度，并补充项目集筛选**（前端过滤或 API 参数） |
| 部门项目人力登记 | `panel-manpower` | ✅ 月/季/年子 Tab + **左右分栏冻结表** + 动态部门列矩阵 | 扁平 7 列表 | **不得按原型 flatten**；仅在现有矩阵上压缩行高、工具条 |
| 项目风险登记 | `panel-risk` | ✅ 可编辑表格 + 风险分析弹层 | 级别/状态下拉筛选 | **保留行内编辑与分析**；筛选可作为增强 |
| 设置 | `panel-settings` | ✅ 权限说明、用户管理（管理员） | ❌ 无 | **必须保留**第四 Tab |

#### 1.4.3 表格与样式（现状可度量）

| 项 | 现状（`index.html`） | 目标（本方案） |
|----|---------------------|---------------|
| `body` 字号 | `15px` | **降至 14px**；表格内统一 **13px**，表头统一 **12px** |
| 单元格 padding | `th, td` 默认 **`11px 10px`** | **`6px 10px`**（约减 10px 行高） |
| 表头（人力） | 双行 + 渐变背景，`padding: 10px 8px` | 表头 **34px**，padding **0 10px** |
| 表格容器 | `.table-shell`，`max-height: calc(100vh - 260px)` | 保留滚动容器；随顶栏变矮调整 `260px` 偏移量 |
| 项目集条纹 | `.manpower-set-stripe-b` 暖色块（注释标明**有意保留**） | **保留**部门/项目集配色语义，不改为纯灰斑马纹 |
| 阶段/风险表 | `#phase-table`、`#risk-table` 动态渲染 | 保留 DOM 结构，只改 CSS token |

#### 1.4.4 交互与业务能力（原型未覆盖，优化不得删除）

- **鉴权**：`pmFetch` + Cookie 会话；`pmIsAdmin()` 控制编辑按钮（`.phase-edit-only` 等）
- **编辑模式**：各业务 Tab 底部 `panel-actions`（编辑 / + 新增 / 保存）
- **分析能力**：`项目阶段状态分析`、`项目月度人力分析`、`项目风险分析` 三个入口保持同一按钮样式；分析弹层继续使用现有 Chart.js 能力
- **人力矩阵**：`+ 部门分组`、表头改列名、左右表滚动同步、月/季/年汇总
- **数据持久化**：对接 `/api/v1/*`；非原型中的纯前端 `dataset` 过滤

#### 1.4.5 三份材料对照总表

| 维度 | 生产 `index.html` | 原型 `ipd-pmo-redesign.html` | 本方案采纳 |
|------|-------------------|------------------------------|-----------|
| LOGO | `projectguard-logo.png` | 文字 IPD-PMO | **生产** |
| 顶栏高度 | ~12.5vh（过大） | 48px | **向原型高度靠拢，结构用生产** |
| Tab 数量 | 4（含设置） | 3 | **生产** |
| 人力表结构 | 动态矩阵 + 冻结列 | 静态 7 列 | **生产** |
| 筛选 | 年月 / 无（风险） | 下拉即时过滤 | 阶段状态采用 **年月 + 项目集筛选**；其他模块生产为主，过滤为增量 |
| 分页 | 无（区域内滚动） | 无 + 表尾条数 | **表尾条数可增量** |
| 主色 | `#1677ff` | `#1890ff` | **生产** |
| 表格密度 | 偏松（padding 11px） | 36px 行高 | **目标态** |

#### 1.4.6 修订后的优化边界（Scope）

**在范围内：**

- 压缩顶栏、工具条、单元格 padding，提升同屏行数
- 统一三业务 Tab 的工具条高度、表格边框/圆角、表尾统计样式
- 将现有 CSS 变量（`--accent` 等）整理为文档化 token，减少魔法数

**不在范围内（除非单独立项）：**

- 替换 ProjectGuard 品牌或移除 LOGO
- 将人力登记改为原型级扁平表
- 删除设置 Tab、编辑/保存、分析图表、鉴权
- 用原型静态 JSON 替代现有 API 数据流

## 2. 问题诊断

### 2.1 问题一：信息密度不足

**现象：**

- 表格字体 15–16px，行高 50–60px
- 筛选区按钮 36–40px 高，占据大量垂直空间
- 标题区上下各有 20–30px 空白
- **结果：一屏仅展示 3–4 行数据，用户频繁翻页**

**影响：**

- 浏览效率低，无法快速对比多行数据
- 无效空白和过大控件挤占了数据展示空间

### 2.2 问题二：空间利用率低

**现象：**

- 筛选条件区控件尺寸过大，可压缩约 50% 垂直空间
- 标题区域有大量无效留白
- 表格列宽分配不合理，窄列过宽、宽列过窄

**当前空间分布估算（1080p 视口）：**

```
┌──────────────────────────────────┐
│  标题区      ~80px   (可压缩→40px) │
│  筛选区      ~60px   (可压缩→32px) │
│  操作区      ~40px   (可压缩→28px) │
│  空白区      ~60px   (可消除)     │
│  表头        ~45px   (可压缩→34px) │
│  ─────────────────────────────── │
│  数据行×4    ~220px  (可→18行)   │
│  底部空白    ~60px   (可消除)     │
└──────────────────────────────────┘
```

### 2.3 问题三：视觉一致性差

| 对比项 | 项目阶段状态 | 部门项目人力登记 | 项目风险登记 |
|--------|:----------:|:--------------:|:----------:|
| 页面左侧间距 | ~24px | ~20px | ~28px |
| 顶部距离导航 | ~16px | ~24px | ~12px |
| 底部留白 | ~60px | ~45px | ~70px |
| 卡片圆角 | 4px | 6px | 无 |
| 表格边框样式 | 实线 | 虚线 | 无边框 |

三个核心模块缺乏统一的视觉规范，用户切换模块时体验割裂。

## 3. 设计目标与原则

### 3.1 量化目标

| 指标 | 当前值 | 目标值 | 提升幅度 |
|------|:-----:|:-----:|:-------:|
| 单屏可见数据行数 | 3–4 行 | ≥15 行 | **+300%** |
| 表格行高 | 50–60px | 36–38px | **-35%** |
| 筛选区高度 | ~60px | ~32px | **-47%** |
| 有效信息占比 | ~40% | ≥75% | **+88%** |
| 页边距一致性 | 不统一 | ±2px | — |

### 3.2 设计原则

**原则一：紧凑但不拥挤**

- 压缩无效空白，保持可读性与可操作性
- 关键操作区域点击热区 ≥24×24px

**原则二：清晰但不空洞**

- 通过色彩层次（背景色、边框色、分割线）建立视觉秩序
- 高信息密度下，通过斑马纹和 hover 高亮保持可读性

**原则三：统一但有层次**

- 全局统一间距、字号、色彩规范
- 通过卡片边框、分割线区分筛选区与表格区

**原则四：简洁聚焦（数据量 ≤20 条场景）**

- 全量展示优于分页；筛选 change 即时过滤
- 页面标题与顶部导航去重，以导航为准

## 5. 优化方案详述

### 5.1 顶部导航：在现有结构上压缩高度

**现状问题：** `.tabs-sticky` 使用 `--nav-vh-eighth: calc(100vh / 8)`，1080p 下顶栏约 **135px**，是「一屏只能看几行」的主因之一。

**策略（保留 LOGO + 四 Tab + 用户区）：**

- **不**用原型「◆ IPD-PMO」替换 `projectguard-logo.png`
- 将顶栏目标高度改为 **`48px`–`56px` 固定**（或 `min(56px, 10vh)`），同步调整：
  - `.app-brand img` 的 `max-height`
  - `--tabs-menu-height`（现为顶栏 2/3，可改为 `min(36px, 100%)`）
- 内容区**已无**重复 `h1` 大标题（现有实现符合「标题去重」）
- 切换 Tab 时**不强制**清空年月选择（与原型筛选重置不同）；项目阶段状态新增的项目集筛选仅作用于当前面板

**顶栏 CSS 调整方向（在 `.tabs-sticky` 上改）：**

```css
.tabs-sticky {
  --nav-bar-height: 52px;           /* 替代 100vh/8 */
  --tabs-menu-height: 36px;
  height: var(--nav-bar-height);
  min-height: var(--nav-bar-height);
}
.app-brand img {
  max-height: var(--nav-bar-height);
}
.tabs .tab.active {
  background: var(--accent-soft);
  color: var(--accent);              /* 现有 #1677ff，勿改 #1890ff */
}
```

### 5.2 密度优先，但不削弱业务能力

原型面向「≤20 条静态演示」；**生产环境**需在保留编辑、年月、矩阵、设置的前提下提密度：

| 原型建议 | 生产落地 |
|---------|---------|
| 无分页 | ✅ 已采用区域内滚动；可增加表尾「共 N 条」 |
| 无查询/重置 | ✅ 阶段状态以**年月 + 项目集筛选**为维度；人力继续保留年月/季/年维度 |
| 无编辑按钮 | ❌ **必须保留** `.panel-actions` 编辑/保存 |
| 无设置 Tab | ❌ **必须保留** `panel-settings` |
| 无分析图表 | ❌ **必须保留** Chart.js 分析弹层 |

> 当单表行数常态超过 50 行时，再评估虚拟滚动或服务端分页；人力矩阵列数多时的横向滚动现状继续保留。

### 5.3 工具条：筛选与操作同行

- 高度约 32px（控件 30px + `margin-bottom: 12px`）
- 筛选下拉 `.filter-select`：`height: 30px`，`font-size: 12px`，`min-width: 120px`
- 右侧保留「导出报表」等次要操作（`.btn-default`）
- 管理员写操作（新增/编辑/删除）按权限在工具条或行内展示，与现有 `pmIsAdmin()` 逻辑对齐

### 5.4 表格优化（核心）

**优化前后对比：**

| 属性 | 优化前 | 优化后 |
|------|:-----:|:-----:|

- `thead` 与 `th` 设置 `position: sticky; top: 48px`（与顶栏高度对齐），纵向滚动时表头固定

## 8. 交互与组件行为

### 8.1 模块切换（现有逻辑）

生产环境已通过 `.tabs .tab` 的 `data-target` 切换 `#panel-*`，并配合 `role="tab"` / `aria-selected`。**优化时保持该机制**，不改为原型的 `switchTab(idx)` 硬编码。

切换 Tab 时：

- **保留**各面板年月、编辑模式状态（现状行为）
- **不要**照搬原型「清空所有下拉」——生产无项目集下拉时会造成困惑

### 8.2 筛选与数据加载（生产 vs 原型）

| 模块 | 生产现状 | 原型 | 增量建议 |
|------|---------|------|---------|
| 阶段状态 | `#phase-year-input` + `#phase-month-select` → API 拉取 | 项目集/子项目集 `change` 前端过滤 | **保留年月维度，并补充项目集筛选**；优先前端过滤已加载行 |
| 人力登记 | 年月/季/年 → 矩阵 API | 部门下拉 | 可选：高亮某部门列 |
| 风险登记 | 全表 API + 表头排序 | 级别/状态过滤 | 可选：表头筛选或工具条下拉 |

原型 `filterTab0` 类脚本**仅作交互参考**；实施以 `loadSavedData`、`reloadManpowerHeaderAndCurrentMonth` 等现有函数为准。

### 8.3 分析按钮一致性

三个业务模块的分析入口统一为同一套按钮样式：

| 模块 | 按钮文案 | 建议类名 |
|------|---------|---------|
| 项目阶段状态 | 项目阶段状态分析 | `.manpower-analysis-btn` / `.analysis-btn` |
| 部门项目人力登记 | 项目月度人力分析 | `.manpower-analysis-btn` / `.analysis-btn` |
| 项目风险登记 | 项目风险分析 | `.manpower-analysis-btn` / `.analysis-btn` |

当前实现中风险分析入口更接近 `.manpower-subtab` 的视觉，优化时应调整为与另外两个分析按钮一致，保持高度、字号、边框、hover/focus 状态一致。

### 8.4 空态、加载与错误态

| 状态 | 表现 |
|------|------|
| 加载中 | 表格区域 skeleton 或半透明遮罩 +「加载中…」 |
| 无数据 | 表格内居中「暂无数据」，工具条筛选保留 |
| 筛选无结果 | 表体空行 + 表尾「共 0 条记录」 |
| 接口失败 | 表格上方 `message` 条，保留上次成功数据（若有） |

### 8.5 与现有后端的衔接要点

- 保持 [`frontend/index.html`](../frontend/index.html) 既有 API 契约：`pmFetch`、`credentials: 'include'`、管理员写权限
- 列数据仍来自 `/api/v1/phase-assessments`、`manpower-*`、`project-risks` 等路由（见 TDD）
- 迁移时优先替换**布局与表格样式**，业务逻辑函数（`renderPhaseTable` 等）通过适配层逐步收敛，避免一次性重写 `pmBootstrap`

### 8.6 响应式断点

| 视口宽度 | 策略 |
|---------|------|
| ≥1920px | 全列展示，横向无滚动 |
| 1440px | 默认设计基准 |
| 1366px | `.table-wrap` 横向滚动；`thead` sticky 保持 |
| &lt;1366px | 工具条 `flex-wrap`；次要列可考虑隐藏（二期） |
